# M5 — Search with filters: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One search, reachable from every view, that finds any page by name, place, tags, links or text. Its filters are chips: project, folder, tags, links to, links from, image and audio.

**Architecture:**
- **Index:** the vault's SQLite index gains a `page_text` table and an external-content FTS5 table `fts`. Triggers keep `fts` in sync, so every existing write path (`upsert_page`, `upsert_file`, `remove`, `rename`) updates search for free.
- **Queries:** `nimw-index::search` turns the typed text into an injection-safe FTS5 query. It collects the text matches into a temp table, then applies the filters, ranking, facets and snippets with plain SQL over that table.
- **Command:** `search(query)` is the only new command.
- **UI:** a modal `SearchDialog`, with a zustand `searchStore` (80 ms debounce, stale answers dropped, state kept per vault session). It opens from the top bar, ⌘⇧F and View → Search….

**Tech stack:** Rust (rusqlite 0.40 bundled SQLite with FTS5, pulldown-cmark), Tauri 2.12 commands with real-ACL tests, React 19 + TypeScript + zustand, i18next with ICU, Vitest + Testing Library + axe-core, Playwright (Chromium + WebKit).

**Spec:** `docs/superpowers/specs/2026-10-14-m5-search-design.md`. Its §10 amendments override §1–§9.

## Global Constraints

- **Index schema:** `SCHEMA_VERSION = 3`. An index built by version 2 is deleted and rebuilt on open.
- **FTS5 tokenizer:** `tokenize='unicode61 remove_diacritics 2'` and `prefix='2 3'`.
- **bm25 weights:** title 10, name 8, folders 5, tags 6, links 4, body 1.
- **Limits:**
  - at most 50 hits per page of results;
  - Recent is the 20 most recently modified pages;
  - the facets show at most 12 tags and 8 links-to targets;
  - a snippet is about 12 words.
- **Debounce:** the UI debounces typing by 80 ms.
- **Performance (release, `--ignored`):**
  - p95 < 50 ms for `search` on the 10k reference vault (200 queries of 1–3 words plus filter mixes);
  - the first full index, FTS included, in < 30 s;
  - re-indexing a changed file in < 100 ms.
- **Commands:** every command is async through `blocking()`, with a real-ACL test (allowed from `main`, denied elsewhere).
- **Platform and quality floors:**
  - no network;
  - i18n en + es, with ICU plurals (`{count, plural, one {…} other {…}}`);
  - axe-clean in light and dark;
  - full keyboard parity;
  - the Safari 15.0 floor: no `.at(`, `structuredClone`, regex lookbehind, `color-mix()` or `Object.hasOwn`.
- **Snippets** are structured data (`{ text, hit }` parts) and never HTML. Highlights are `<mark>` elements built in React.
- **Filter words** (`#tag`, `in:`, `to:`, `from:`) are the same in every language.
- **Shortcut:** ⌘⇧F on macOS, Ctrl+Shift+F elsewhere. Stay off ⌘⇧N, which M4c takes.
- **Process:**
  - commits are signed, each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - build env: `CARGO_TARGET_DIR=$SP/m5-target`, `NIMW_E2E_PORT=4333`.

## Review Focus

The inputs and failure modes the spec implies that are most likely to bite a person. Each has a test in the task that owns the code.

1. **FTS5 syntax typed as text:**
   - **Input:** `AND`, `"`, `*`, `NEAR(`, `^`, `(`, `-`, `:`, a lone `"`, or punctuation with no word in it.
   - **Expected:** it never errors and never matches everything by accident. A query with no searchable word acts as an empty query.
   - **Tests:** Task 3, `operators_are_text` and `punctuation_only_is_empty`.
2. **The index after a rename or move:**
   - **Expected:** a page renamed or moved, or a folder renamed, is found by its new name and folder and no longer by the old ones. A deleted page disappears from results, and a page that becomes a non-page (invalid UTF-8) leaves `fts`.
   - **Tests:** Task 2, `fts_follows_rename_move_and_delete`.
3. **Accents both ways:**
   - **Expected:** `cancion` finds `canción` and `CANCIÓN` finds `cancion`, in the title, tags and body, with prefixes (`canc`). The UI highlights the accented title text for an unaccented query.
   - **Tests:** Task 3, `accents_and_prefixes`; Task 6, `highlightParts`.
4. **Filters combined with no text:**
   - **Expected:** a tag filter plus a project filter with an empty field lists those pages, newest first, not Recent. Removing the last filter goes back to Recent. A filter whose page or folder doesn't exist gives 0 results with its chip still visible.
   - **Tests:** Task 3, `filters_without_text_and_unknown_references`; Task 7, `SearchDialog` chips.
5. **A stale answer arriving last:**
   - **Expected:** an answer for "dra" that lands after the answer for "dragon" is ignored, and so is any answer that comes back after the vault was switched.
   - **Tests:** Task 6, `searchStore` "drops stale responses".

**Behaviour:**
- `fts_query` splits the text into words and `"phrases"`.
  - Each word becomes `"w"*`, with `"` doubled inside it. A phrase becomes `"a b" *`.
  - Words without a letter or digit are dropped. With no word left, it returns `None`, which is treated as an empty text.
  - `all` joins the words with spaces (AND); `any` joins them with ` OR `.
- **With text:** a temp table `hits(path PRIMARY KEY, score REAL, meta INTEGER)` is filled from `fts MATCH all`. `meta = rowid IN (SELECT rowid FROM fts WHERE fts MATCH '{title name folders tags links} : (any)')`.
- **Without text:** the base is `pages`, with score 0 and meta 0.
- **Filters** become SQL clauses over `h.path` and `p.*`, as amendment §10.12 says:
  - `folder` is resolved in Rust to folder paths, by exact path or by folded name;
  - `links_to` / `links_from` are resolved to one page path: exact path, then `+ ".md"`, then `nimw_markdown::resolve(Wiki, …)`, then a folded title;
  - an unresolvable reference becomes the clause `0`.
- **Order:**
  - with text: `meta DESC, score ASC, length(path), mtime DESC`;
  - without text: `mtime DESC, path`.
- **Recent:** with no text and no filters, the limit is 20, offset 0, and `recent = true`.
- **Facets** are computed per amendment §10.13. Active values are always included; an unresolved `links_to` reads as `{ path: value, title: value, count: 0, active: true }`.
- **Snippets:** only for the page of hits shown, through `snippet(fts, 5, char(1), char(2), '…', 12)` with `fts MATCH '{body} : (any)' AND rowid = ?`. A snippet with no marker becomes `None`.
- **Hit tags:** the page's tags, with matching tags first. A tag matches when its folded form starts with a folded query word, or when it is (or is nested under) a filter tag.
- **Cover:** the resolved `cover` link's target path.

  - `accents_and_prefixes`: `cancion` finds `canción`, `CANCIÓN` finds `cancion`, and `canc` finds both.
