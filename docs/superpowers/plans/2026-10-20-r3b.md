# Round 3b: folder pages, double-click, page icons in lists — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A folder and its same-name page (`X/X.md`) show as one sidebar row that opens the page. Double-clicking a sidebar page opens it in the editor, or renames it if it's already open there. Every page list shows the page's icon in its leading box. The Notion importer writes pages with children as `X/X.md`.

**Architecture:**
- **Pairing rule (Rust, `VaultSession::rename`):** renaming a folder page or its folder in place renames the other one too. The second step is reported as `pair`, so the UI composes both moves before reloading the open page.
- **Folder pages in the UI:** a frontend helper `folderPageOf` hides `X/X.md` from the tree and lets the folder row stand for it.
- **Importer:** chooses `X/X.md` when the export has a folder beside the page.
- **Double-click and icon boxes:** UI-only changes over existing stores.

**Tech Stack:** Rust (liber-session, liber-import, src-tauri DTOs), React 19 + zustand, CodeMirror 6 autocompletion, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-20-r3-feedback-design.md` §6 (folder pages) and §8 (round 3b).

## Global Constraints

- The convention is "inside" only. A folder `X/` has a page when `X/X.md` exists, matching names exactly (spec §6.1). A sibling `X.md` beside `X/` stays an ordinary page.
- Renames go through the existing rename path, so links are rewritten (§6.3). There is no second link-rewriting mechanism.
- en and es i18n stay in sync (`pnpm check:i18n`). Use ICU single braces (`{name}`), never `{{ }}`.
- Zero network requests (P1). The Archive stays read-only: no new actions on archived rows.
- The CSS must pass the existing Safari 15 floor guards (no `:has()`; give every `:focus-visible` its own rule).
- Every commit is SSH-signed and ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never bypass signing.
- The gate is `$SP/check.sh all <worktree>` and must print `ALL-OK`, with its own `CARGO_TARGET_DIR` and `LIBER_E2E_PORT`.
- Branch from `feat/r3`.

## Review Focus

1. **Renaming a folder page to a name its folder can't take.** For example, `A/A.md` → `A/B.md` while `B/` exists beside `A/`. Expected: the whole rename is refused before anything moves, and both files stay put. Test in Task 1.
2. **Renaming the open folder page from its title.** Expected: the editor follows to `Y/Y.md` without ever trying to load the intermediate `X/Y.md`, so there is no "deleted" flash. Test in Task 2.
3. **Double-click right after switching pages.** The first click of a double-click opens a different page. Expected: the editor opens; it does not start a rename, because the decision uses the state *before* the first click. Test in Task 7.
4. **A folder page whose folder is pinned (Scratchpad) or archived.** Expected: the Scratchpad row behaves the same. Archived folder-page rows open their page read-only and offer no new menu actions. Test in Task 3.
5. **A Notion page with children whose folder name was numbered** (`Home 1/`). Expected: the page goes to `Home 1/Home 1.md`, never `Home 1/Home.md`, and links to it resolve. Test in Task 6.

**Interfaces:**
- Produces: `RenameOutcome.pair: Option<(String, String)>`. This is the second rename, given in the paths that exist after the first one. In JSON it is `pair: [string, string] | null`.
- Produces: `fn paired_rename(from: &VaultPath, to: &VaultPath, is_folder: bool, exists: impl Fn(&VaultPath) -> bool) -> Option<(VaultPath, VaultPath)>`, a pure function. It covers two cases:
  - **Folder renamed in place** (same parent, new name), with `from/<from name>.md` existing → `(to/<from name>.md, to/<to name>.md)`.
  - **Page renamed in place** (same parent `P`, not the root, new stem), where `P`'s name equals the old stem → `(P, parent(P)/<new stem>)`.
  - Anything else → `None`. That includes moves to another parent, which is how "Use X.md as this folder's page" in Task 4 works.
