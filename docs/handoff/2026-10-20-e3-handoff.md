# Encryption E3 hand-off: encrypted storage (2026-10-20)

**Where it is.**

- **Branch:** `feat/enc-e3`, from `main` at `1ec1c13` (E1 and E2 merged). HEAD is `4f53f74`. Nothing is merged and nothing is pushed.
- **Plan:** `docs/superpowers/plans/2026-10-20-enc-e3-encrypted-storage.md`.
- **Spec:** `docs/superpowers/specs/2026-10-20-encryption-design.md`. Section 16, "E3 as built", holds the rulings as built, the leak audit, the residuals and the known limitations. This hand-off summarises it and does not repeat it.
- **Short references:** `docs/architecture/storage-seam.md` ("`EncryptedStorage` (E3, as built)") and `docs/architecture/index-and-database.md` section 1a (the in-memory index).
- **Ledger and per-task reports:** `.superpowers/sdd/2026-10-20-enc-e3-encrypted-storage/` (`progress.md`, `task-N-report.md`, `final-fix-report.md`). The folder is git-ignored, so it exists only on this machine.
- **Constraint from the maintainer:** no app builds (Mac or Windows bundles) until the whole encryption feature (E3 plus E4) is merged.

**What E3 is.** E2 put every byte of vault content behind one trait, `Storage`. E3 adds the second implementation, `EncryptedStorage`, which writes exactly format v1 (the vectors did not change). On top of it: a session that opens an encrypted vault with an in-memory index, the desktop commands to create, unlock and lock one, encrypted recordings, decrypted copies for opening attachments, and OS lock signals (sleep, screen lock). There is no UI yet. E4 adds the screens and consumes the command contract in section 4.

### 2.5 The performance test

```sh
LIBER_PERF=1 cargo test --release -p liber-session --test encrypted_perf -- --nocapture
```

Unlock to the first successful search on a sealed 10,000-note vault. Measured **1.75 s** (budget 3 s): about 1.71 s indexing and 34 ms for the first search. This is a **warm** figure: it is taken right after sealing, with the ciphertext in the OS file cache. A cold unlock (after a reboot or a sync) reads from disk and is slower. Without `LIBER_PERF=1` and a release build the test returns early.

## 3. Architecture map

### Storage layer, `crates/liber-vault/src/storage/encrypted/`

| File | Holds |
|---|---|
| `mod.rs` | `EncryptedStorage`: create, unlock, lock, `vault_kind`, reads, listing cache, `same_entry`, `os_path`, `unreadable()`, salvage, the `Drop` that clears keys |
| `names.rs` | Name encoding and decoding, long names (`.liberl` plus `.libern` side file), conflict and duplicate suffixing (`suffixed`), `one_component` name checks |
| `write.rs` | Atomic writes, `create_new` and `NewFile::finish`, folders, renames, trash, `finish_or_keep` |
| `watch.rs` | The watcher: maps physical events to logical paths through the parent listing; `Overflow` when unsure |
| `header.rs` | Header read, merge and write (`write_header`), rotation helpers, epoch bookkeeping |

`Storage::as_encrypted()` (default `None`) is the one trait addition. `crates/liber-vault/src/error.rs` gained `NotEmpty`, `NotPermitted`, `Damaged`, and `io_err` now turns an I/O error that carries `Locked` into `Locked`. Test hooks (`create_insecure`, write-failure hooks) sit behind the `test-params` feature.

### Session, `crates/liber-session`

`VaultSession::open_encrypted` builds the session with a `:memory:` SQLite index (`temp_store = MEMORY`). The session's index is an `Option<Index>`; every index-backed call goes through a fallible accessor that returns `Locked` after `lock()`. Lock stops the watcher, then drops keys and index together. Unlock builds a fresh session and re-indexes everything (1.75 s for 10,000 notes). Open detects the kind via `vault_kind`: encrypted only if `liber-vault.json` parses and `d/` is a folder.

### Desktop, `apps/desktop/src-tauri/src`

| File | Holds |
|---|---|
| `encryption_commands.rs` | `vault_create_encrypted`, `vault_unlock`, `vault_lock`, `security_change_passphrase`, `security_new_recovery`, `vault_unreadable`, `vault_reveal_unreadable`, `attachment_open_decrypted`, `security_reset_rollback_memory` |
| `epochs.rs` | The rollback memory `vault-epochs.json` (vault id to epoch): atomic writes, serialized, fails closed when damaged, reset moves it aside |
| `decrypted_copies.rs` | Decrypted attachment copies in `<temp>/liber-<pid>-<random>/`, wiped on lock and quit, startup sweep of dead runs (never follows a link, unix owner check) |
| `audio_commands.rs` | The encrypted recording path: takes in `.liber/recording/<take>/`, `sync_data` about every 2 s, Stop streams into the final clip, lock or vault switch keeps the take, salvage at unlock |
| `lock_signals.rs` | Sleep (5 s clock-jump tick, over 30 s means slept), macOS `com.apple.screenIsLocked` observer with DeliverImmediately, Windows `OpenInputDesktop` poll every 5 s. Emits `vault:lock-request { reason }` only while an encrypted vault is open |
| `error.rs` | New error kinds: `locked`, `wrongSecret`, `rollback`, `damaged` (plus `notPermitted` and `conflict` reused) |
| `vault_commands.rs`, `state.rs` | `leave_encrypted` stops a take and locks the old session on vault switch or close; `set_session` locks an outgoing encrypted session before wiping copies |

### Tests worth knowing

`crates/liber-vault/tests/encrypted_storage.rs`, `encrypted_names.rs`, `encrypted_xcheck.rs`, `write_ops.rs`; `crates/liber-session/tests/encrypted_perf.rs`, `rename.rs`; `apps/desktop/src-tauri/tests/encryption_commands.rs`, `encrypted_canary.rs`, `release_features.rs`.

## 4. The E3 to E4 command contract

The contract is the comment block at `apps/desktop/src/ipc/index.ts` line 312 ("E3: encrypted vaults (the E3 → E4 contract; E4 adds the calls)"), with the TS types `UnlockSecret`, `CreatedEncryptedVault`, `UnreadableEntry`, `VaultLockedPayload` and `VaultLockRequestPayload`. In short:

| Command or event | Notes |
|---|---|
| `vault_create_encrypted { path, passphrase }` | Returns the vault info and the recovery code, shown once. A create that fails after the vault was made is undone |
| `vault_unlock { path, secret }` | `secret.kind` is `passphrase` or `recovery`. `info.recovered` lists clips saved from takes a lock or crash left |
| `vault_lock {}` | Emits `vault:locked` to main. `notPermitted` on a plain vault |
| `security_change_passphrase { current, next }` | |
| `security_new_recovery { passphrase }` | Returns the new code. `conflict` if another device's code won the merge (none shown) |
| `vault_unreadable {}` and `vault_reveal_unreadable { osPath }` | List entries that can't be read, and show one in Finder |
| `attachment_open_decrypted { path }` | Decrypted copy, wiped on lock. `notPermitted` on a plain vault |
| `security_reset_rollback_memory {}` | Only after the user confirms. `notPermitted` while the store is readable |
| event `vault:lock-request { reason: "sleep" \| "screenLock" }` | E4 must lock in answer |

Error kinds E4 must handle: `locked`, `wrongSecret` (text must say "wrong passphrase or recovery key, or the vault's header is damaged"), `rollback`, `damaged` (including the form naming `vault-epochs.json`), `conflict`, `notPermitted`.

Two E4 follow-ups from the ledger: `VaultInfo.recovered` uses the recorder Start's shape (objects with `.path`), but E4 Task 1 typed it `string[]`; fix at the E4 rebase. And `liber.favoritesCollapsed:<vault root path>` in `localStorage` holds the vault's folder path; key it off for encrypted vaults (E4 Task 6).

## 5. Rulings made during execution

Grouped by topic. Each has its cost if wrong. The plan's own eight rulings and twelve build rulings are in the spec section 16; the list below adds the execution-time ones from the ledger.

### Names

| Ruling | Cost if wrong |
|---|---|
| Names are case- and NFC-insensitive on every OS, Linux included. A synced vault behaves the same everywhere | Two notes differing only in case can't coexist in an encrypted vault |
| `:` and `\` are refused in encrypted names on every OS (UI already refused `:`) | A note with `:` written by an outside tool shows as unreadable, never deleted |
| Names a sync duplicated stay readable (final review C1, reversing Task 1's "both unreadable"). The first by physical name keeps the name, others become `<name> (duplicate N)`. Case variants are grouped too | A duplicate shows under a suffixed name the user must merge by hand |
| Unreadable entries are never touched (no delete, rename or overwrite) | A bad entry stays until the user removes it |
| A long name's side file stays while a sibling conflict copy still names it | An occasional stale `.libern` lingers until the copy goes |
| `Overwrite` with no logical entry commits as `CreateOnly`, so it can't overwrite an unreadable entry with the same physical name | None |

### Open, damage and rollback

| Ruling | Cost if wrong |
|---|---|
| Encrypted iff the header parses and `d/` is a folder. Header with no `d/`, or an unparseable header beside `d/`, is `Damaged` and never opens as plain | A damaged vault needs a manual fix instead of silently opening plain (intended) |
| Header read bound is the format's own 1 MiB maximum, not 64 KiB | A vault with many keyring slots would read as `Damaged` |
| `VaultError::Damaged` has its own error kind `damaged` | One extra kind |
| MAC failure after a slot unwraps reports `wrongSecret`, like a wrong passphrase | A user with a damaged header may think they forgot the passphrase (the UI text mitigates; revisit with a `liber-crypto` distinction) |
| Epoch check comes before the header merge at unlock; every header write merges the on-disk header first | None (the only order that never writes a rolled-back header) |
| A header that changed on disk and won't merge is `conflict`, not `damaged` | None |
| A corrupt `vault-epochs.json` fails closed as `damaged`; `security_reset_rollback_memory` moves it aside, never silently | One extra command |
| A create that fails late removes the just-created header and `d/`; the epoch store is validated before creating | None |
| A new recovery code that loses the merge is refused with `conflict`, so a code that doesn't open the vault is never shown | None |

### Writes, locks and the index

| Ruling | Cost if wrong |
|---|---|
| A save in flight when `lock()` runs still commits its ciphertext | None (only ciphertext is written) |
| `trash_os` sends the ciphertext entry to the OS trash, never plaintext | None |
| `lock()` drops and replaces the index connection rather than DELETE plus VACUUM | None |
| The lock rework (RwLock, no cache lock across disk I/O, `trash::delete` outside the mutexes, watcher not holding keys during listing) landed in Task 4, where the first concurrent consumer appeared | Task 4 was larger |
| Session index is `Option<Index>`; every index-backed call is `Locked` after lock | None |
| Windows open-time swap check uses size and mtime (std has no stable file index); the unix inode check is the real guard | A narrow Windows TOCTOU window (ciphertext only) |
| Merged header conflict copies go to the OS trash, never deleted | None |
| `VaultError::NotEmpty` and `NotPermitted` added; `begin_rotation_insecure` added under `test-params` | A little gated code |
| A README truncated by a crash is not auto-repaired | User deletes it by hand |

### Desktop, copies and recordings

| Ruling | Cost if wrong |
|---|---|
| Decrypted-copy sweep acts only on real directories owned by this user (`lstat`, re-checked before removal) | None |
| Windows partial wipe removes `.lock` last, so a copy that couldn't go is found by the next sweep | None |
| Decrypted copies stream and are removed on failure; errors carry `locked` or `damaged` | None |
| `attachment_open_decrypted` refuses plain vaults with `notPermitted` | None |
| Recordings live in `.liber/recording/` (never the app cache); a failed finish keeps the temp file (`finish_or_keep`) | A huge crashed take waits for a later fix if it can't stream (streaming was possible, so no limit applies) |
| Stop and recovery stream; a lock mid-take stops it and keeps it; leaving an encrypted vault locks it | None |
| Lock during Stop reports `locked` (root fix in `io_err`) | None |
| `VaultInfo.recovered` added so E4 can toast | One DTO field |

## 6. Deferred minors and known limitations

"Lands in" is a suggestion. The full list of limitations is in the spec section 16 under "Known limitations".

### Lock signals (E4 or E5)

| Item | Suggested fix | Lands in |
|---|---|---|
| **No pre-sleep lock signal.** Today the vault locks after wake (clock jump over 30 s, checked every 5 s), so keys stay in RAM through sleep | macOS: observe `NSWorkspaceWillSleepNotification`. Windows: `WM_POWERBROADCAST` with `PBT_APMSUSPEND`. Add a backend fallback lock (lock in Rust, not only on a front-end event) so the vault locks even if the WebView is unresponsive | E4/E5 |
| No real sleep, screen-lock or Windows lock was exercised in tests. Only `slept` and `newly_locked` are unit-tested; the macOS observer is registered only on the real runtime | Do the manual checks in section 7 | E4 manual |
| Linux has no screen-lock signal | Only the sleep jump and the idle timer lock there; a D-Bus listener is a later option | Later |
| Windows lock can false-positive on UAC, Ctrl+Alt+Del, services and disconnected RDP (no input desktop) | Accepted, fail-safe | None |

### Duplicates and names (E5 or later)

| Item | Suggested fix | Lands in |
|---|---|---|
| A cached listing under `(duplicate 1)` can go stale after promote, write, demote. Transient; the session reconcile re-reads | Invalidate the listing on promote/demote | Later |
| A later-synced copy that sorts first takes the plain name and demotes the old primary; links follow the newcomer | A merge helper in the UI, or choose the primary by something other than physical order | E5 |
| Case-only rename of a primary onto a duplicate's variant gives a confusing `AlreadyExists` | Detect the case and give a clearer message, or allow the swap | E4 text or later |
| The Rust "header changed on disk" message lost its "lock and unlock again" hint | E4 words the `conflict` error itself | E4 |
| Watcher: an event for a duplicate removed after its listing was dropped is named by the plain name, so the session gets `Removed(<plain>)` for an entry that still exists. Harmless if the session stats on `Removed`; not verified | Verify the session behaviour; map through a remembered listing | E5 or later |
| Watcher: an event in a duplicate folder the cache hasn't seen maps to `Overflow` (a rescan) | Accepted, only slower | None |
| Watcher: long-name remove or rename shows as `Overflow`; a concurrent `unreadable()` can briefly list a side file mid-place | Accepted | None |

| A folder with no header whose `d/` holds only encrypted folders (no file suffixes) still reads as plain | Repair flow | E5 |

## 7. Manual checks for the maintainer

None of these can run in CI, and the maintainer's rule is not to send global key codes to the Mac while testing. Do them by hand.

1. **macOS screen lock with another app in front.** Open an encrypted vault in Liber Linteum (E4's UI is needed to see the result; until then, check the `vault:lock-request` event in a dev build). Put a different app in front. Lock the screen (Control-Command-Q or the Lock Screen menu item). Wait about 10 seconds. Unlock the Mac. Expect the vault to be locked on return. This is the check for the `DeliverImmediately` fix; with the default coalescing the lock arrived only after you came back and reactivated the app.
2. **Sleep.** Close the lid or sleep the Mac for over 30 seconds, wake it. Expect the vault locked within about 5 s of wake. Remember this is the post-wake path; the pre-sleep signal is a known gap (section 6).
3. **Windows lock.** On a Windows machine with a build of the branch, open an encrypted vault, press Win+L, wait over 5 s, unlock. Expect it locked. Also check that a UAC prompt locks it (fail-safe, expected).
4. **A recording across a lock.** Start a take in an encrypted vault, lock (or sleep), unlock again. Expect a recovered-clip toast (once E4 shows it) and a `-recovered.wav` beside the page's attachments.
5. **The xcheck before a release** (section 2.6), plus the perf run (section 2.5) on a cold cache after a reboot, to know the real first-unlock time.
6. **Crash cleanup.** Open an attachment from an encrypted vault, force-quit the app, restart. Expect the `liber-<pid>-...` folder in the temp dir to be gone after the startup sweep.
