# Encryption E2 hand-off: the storage seam (2026-10-20)

**Where it is.**
- **Branch:** `feat/enc-e2`. It was rebased twice onto `main` and now sits on `1f88162`. Nothing is merged and nothing is pushed.
- **Plan:** `docs/superpowers/plans/2026-10-20-enc-e2-storage-seam.md`.
- **Spec:** `docs/superpowers/specs/2026-10-20-encryption-design.md` §8 (the seam) and §13 (E2: no behaviour change).
- **Short reference:** `docs/architecture/storage-seam.md`. It covers the trait, what stays outside the seam, the guard, and running the suite on another storage.
- **Ledger and per-task reports:** `.superpowers/sdd/2026-10-20-enc-e2-storage-seam/` (`progress.md`, `task-N-report.md`).

**What E2 is.** Every byte of vault content now goes through one trait, `Storage`. `Vault` owns a `Box<dyn Storage>`, and `PlainStorage` keeps the pre-E2 behaviour. E3 adds `EncryptedStorage` behind the same trait. The raw escape hatches `Vault::fs_path` and `visible_fs_path` are gone.

A guard test fails the build on a new direct file-system call in production code. A test-only switch, `LIBER_TEST_STORAGE`, runs the whole Rust suite on a second storage.

## 2. The test-storage switch: how to run it

```sh
# the default (plain), as always
cargo test --workspace
# the whole Rust suite on PassThrough
LIBER_TEST_STORAGE=pass-through cargo test --workspace
# the same thing, spelled out (also works)
LIBER_TEST_STORAGE=pass-through cargo test --workspace --features test-storage
# one crate also works, liber-vault's own integration tests included
LIBER_TEST_STORAGE=pass-through cargo test -p liber-session
```

**How it is wired.**
- `liber-vault/Cargo.toml` declares `[features] test-storage = []`.
- The feature is turned on only from `[dev-dependencies]`: in liber-session, liber-import, src-tauri, and in liber-vault itself (a self dev-dependency, `liber-vault = { path = ".", features = ["test-storage"] }`). Without that self-entry, `-p liber-vault` would run its integration tests on plain storage while the variable said otherwise.
- `cargo tree -e normal` shows `liber-vault` with no features for the desktop app, so release builds never read the variable.

**Results at the end of E2.** 806 passed, 0 failed, 5 ignored on plain. The same counts on pass-through, with or without `--features`.

**What the switch does not cover.**
- Tests that build their own storage (`PlainStorage::open`, `Vault::open_with` with a test `Spy`) ignore it.
- `vault_icon_at` reads through `PlainStorage` directly.
- `liber-testkit` writes fixtures with `std::fs`. That is fine for plain and pass-through, but E3's `encrypted` value needs fixtures written through `Storage`.

## 5. What E3 must do (requirements gathered in E2)

1. **Implement `Storage::same_entry` for `EncryptedStorage`.** Since the final review (I2) it is a trait method: `PlainStorage` resolves both paths and compares canonical paths, and `Vault::same_entry` forwards to the storage. E3 compares logical paths after its own name resolution (case folding included), with no decryption of content. Callers are in `liber-session/src/rename.rs` (the case-only rename and folder-reuse paths).
2. **`os_path(_, Reveal)` must refuse hidden names,** as `PlainStorage` does (Task 5 ruling). With no symlinks, the name alone decides.
3. **Dropping the `WatchGuard` must drop the sink.** `Vault`'s debounce thread ends only when the sink is dropped (`storage/mod.rs` doc).
4. **`vault_icon_at(root)` hardcodes `PlainStorage::open`.** It serves the recent list without opening a session. Route it through `open_storage`, or the unlock path, or give encrypted vaults no icon in the recent list.
5. **Add `encrypted` to `LIBER_TEST_STORAGE`,** and make `liber-testkit` fixtures go through `Storage`: today they write plaintext with `std::fs`.
6. From the plan's trait notes (spec §4–§5):
   - `os_path(Open)` returns `Err(NotPermitted)`; the app layer asks the user before writing a decrypted copy (§5.5). `FileUrl`/`Reveal` are refused.
   - `create_new` returns a `NewFile`: `flush()` is durability only, `finish()` commits, and a drop without `finish` deletes the temp file (final review I1).
   - `watch` sends `Overflow` for lost events and root-level changes (final review M4).
   - `Meta.len` is the logical size (§9 formula).
   - The epoch high-water mark lives in app settings (outside the seam).
   - `EncryptedStorage` validates exactly one `Normal` component per decrypted name and caps the `.libern` side-file read.
   - Recordings use `create_new` + `replace_atomic` + `remove_file`, with recovery listing `.liber/recording/` via `children`.
7. **Audio and index**, which stay outside the seam: takes move into the vault per spec §4.2, and the index uses `:memory:` for encrypted vaults per §5.1.
8. **Keep the guard green.** A new direct call must go through `Vault`, or carry `// seam: outside (<reason>)` only if it never touches vault content.
